# Bubble Bounce — BACKEND (game server)

Frontend (3D client) lives at `../Bubble-bounce`. Colyseus + Mongo, ported from `C:\ThreeJS\Bowling-roll\Bowling-roll-backend` (reduced to progress saving, the roster and leaderboards).

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client `src/net.js` calls `joinOrCreate("world", { userId, username, pfp })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved (the client keeps their progress in the browser). `/health` for Legion; `/monitor` and the playground are dev-only.
- Messages client -> server: `saveProgress` (the whole client `state`, debounced client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session). Server -> client (private): `progress` (the saved doc, sanitized, + `serverTime`), `noProgress` (new account, guest or no database: the client keeps its state and saves it), `serverError` (the save could not be read: saving stays off so it is never overwritten), `leaderboard`. Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp`.
- Save fields (`PlayerDoc`; exactly the client's `src/state/game.js` `state`, bounded in sanitize.ts, anything else dropped): `breath`, `wins`, `rebirths`, `level`, `xp`, `bestDistance` (`$max`, never drops), `equippedBubble`/`bubbles` (equipped must be owned), `pets { owned[{id,type,golden}], equipped[ids], discovered[], nextId, autoDelete }`, `wands { owned, equipped }`, `boosts { inventory, active[{id,until}] }`, `gifts`, `daily`, `spin`, `goalIndex`, `codes`, `tutorial`. Server-written only: `lastSeen`, `username`.
- Spin, daily and gifts are client-side rules for now (stored as part of the save, not server-authoritative).
- Leaderboards (`src/leaderboard.ts`): top `LEADERBOARD_SIZE` by `LEADERBOARD_STATS` (`rebirths`, `wins`, `breath`, `bestDistance`), cached process-wide, sent after each load and every `LEADERBOARD_EVERY_MS`; `leaderboard` { boards, ranks }.
- `src/constants.ts` bounds must cover the client's `src/config/mechanics.js` (ids match `ID_PATTERN`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` builds + tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` from `src/constants.ts`. Needs repo var/secret `LEGION_GAME_ID` (= `bubble-bounce`) and secret `LEGION_DEPLOY_TOKEN`.
